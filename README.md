## Code Review Process

This repository is used for programming practice and code review while you are learning OOP244.

Assignments will be added to this repository one at a time. Complete only the most recently assigned work unless you are specifically asked to revisit something earlier.

### How the Review Process Works

1. Read the assignment carefully and complete the requested work yourself.

2. Commit and push your work to your GitHub repository when you are ready for it to be reviewed.

3. Your code will be reviewed for:
   - correctness;
   - program logic;
   - readability;
   - appropriate use of the programming concepts currently taught in OOP244;
   - coding style and formatting;
   - consistency;
   - proper use of functions, variables, conditions, loops, memory, classes, and other concepts appropriate to the assignment.

4. A review will be added to your assignment folder in a file such as:

   `feedback1.md`

   If another review is needed, additional files will be added:

   `feedback2.md`, `feedback3.md`, and so on.

5. **Do not modify, rename, delete, or replace any `feedback#.md` file.**

   Feedback files are part of the review history and must remain exactly as they were provided.

6. Read the latest feedback carefully and correct the issues identified in your code.

7. Commit and push your corrections when they are ready for another review.

8. This process will continue until the assignment has been completed properly. Once the required corrections have been made and the code demonstrates proper programming practices, the next assignment or assignment step will be added to your repository.

### Important Expectations

The purpose of these exercises is not simply to make the program work.

You are learning how to write **correct, clear, maintainable, and properly structured code**.

Code that happens to produce the correct result may still require correction if it contains poor logic, unnecessary complexity, inconsistent formatting, unsafe practices, or programming habits that can lead to problems later.

Feedback will explain what should be improved and why. It will **not provide the completed solution for you**. You are expected to understand the feedback and make the corrections yourself.

### Do Not Use AI or Code-Generation Assistance

These exercises are intended to develop **your own programming ability**.

Do **not** use Large Language Models or AI assistants such as ChatGPT, Copilot, Claude, Gemini, or similar tools to write, complete, correct, or generate your code.

Do not use AI-powered code completion, automatic solution generation, or any other tool that writes significant portions of the solution for you.

If a tool is doing the thinking, designing, debugging, or coding for you, then you are not developing the skills these exercises are intended to build.

Using these tools may help you finish an assignment faster, but it can seriously damage your progress as a programmer. You may appear to be succeeding while important weaknesses in logic, problem solving, syntax, debugging, memory management, or program design remain hidden.

Those weaknesses become much more difficult to fix later, especially as OOP244 becomes more advanced.

The purpose of this practice is to identify those weaknesses **now**, while the programs are still small and the problems are easier to correct.

If you use AI or code-generation tools to complete these exercises, you defeat the entire purpose of this project and reduce the value of the feedback you receive.

Write the code yourself, make mistakes, read the feedback, understand what went wrong, and correct it yourself. That process is where the learning happens.

### Coding Style

Follow the coding-style requirements provided for OOP244.

For stylistic choices that are not specifically required, use a recognized programming style and apply it consistently throughout your code.

Consistency is important. Do not randomly change indentation, spacing, brace placement, naming conventions, or formatting from one part of the program to another.

As a beginner programmer, functions should normally have **one return statement**. Avoid multiple or early returns unless your professor specifically tells you otherwise.

### Course-Level Programming Concepts

Use only programming techniques and concepts appropriate to your current level in OOP244 and to the assignment being completed.

Do not replace foundational programming exercises with more advanced C++ facilities simply because they make the task shorter.

For example, unless an assignment specifically permits them, do not use advanced library features such as STL containers or `std::string` to avoid practising the lower-level programming concepts the assignment is intended to teach.

The objective is to build a strong programming foundation, not merely to produce the shortest possible solution.
